## 4. PHASE 2 ROADMAP (Post-MVP)

These are the heavier features from the legacies, ordered by value/effort:

### P2-A: Voice Support (Whisper) — ~4h
```
lib/bot/voice.ts
  → downloadVoiceMessage(fileId, botType)
  → transcribeWithWhisper(buffer)  // OpenAI Whisper API
  → correctTranscription(text, rubro)  // domain-specific corrections

Webhook addition (both bots):
  if (message.voice) {
    const text = await transcribeVoice(message.voice.file_id, botType);
    await sendMessage(chatId, `📝 Escuché: "${text}"`, ...);
    // Route through existing command/synonym detection
  }
```
**Pre-req:** OpenAI API key for Whisper. ~$0.006/minute of audio.
**Value:** Huge for field users (real estate agents taking photos + dictating description).

### P2-B: NLP Intent Router — ~6h
```
lib/bot/nlp-router.ts
  → classifyIntent(text, rubro)  // Kimi or Claude API call
  → Returns: { intent: 'SELL'|'QUERY'|'UPLOAD'|..., entities: {...}, confidence: number }

Use cases by rubro:
  retail: "vendí 2 jeans azules" → SELL intent → create sale
  real-estate: "departamento 3 dormitorios ñuñoa" → QUERY → search
  lab: "registrar lote 5000 unidades paracetamol" → ADD_INVENTORY
```
**Pre-req:** LLM API call per message = cost + latency (~1-2s). Consider only activating for non-command text.
**Value:** The "wow factor" — transforms bot from command tool to conversational partner.

### P2-C: Conversational State (IRCE) — ~8h
```
lib/bot/conversation-state.ts
  → States: idle → collecting → confirming → executing
  → Stored in: active_sessions table (per user, per tenant)
  → Each rubro defines its flows:
    retail: sell_flow, add_product_flow, rectify_flow
    real-estate: property_inquiry_flow, schedule_visit_flow
```
**Pre-req:** P2-B (NLP router) should exist first to classify intents.
**Value:** Enables multi-turn conversations ("¿De qué color?" → "azul" → "¿Talla?" → "M").

### P2-D: NLP Search for Retail — ~3h
```
// Extend search-properties.ts pattern to products
lib/bot/search-products.ts
  → extractProductFilters(text)
  → "jeans azules talla M menos de 20 lucas"
  → { category: 'jeans', color: 'azul', size: 'M', max_price: 20000 }
```
**Value:** Lets customers search via bot. Currently only inmobiliario has search.

## 5. THE getUserTenant() LESSON (Architecture Note)

The 1:1 assumption was wrong. A Telegram user can be linked to multiple tenants across rubros. The fix:

```
OLD (broken): .limit(1).single() → grabbed random tenant
NEW (correct): .order('activated_at', desc).limit(10) → filter by rubro → pick most recent
```

**Rule for all future bots:** `getUserTenant()` MUST filter by the bot's expected `rubro_type`. Never assume a user has only one tenant.

This also means the `telegram_users` table supports a user being in:
- A retail store (via ropero bot)
- A real estate office (via inmobiliario bot)
- A lab (via future lab bot)

All simultaneously. The rubro filter in `getUserTenant()` is what makes this work cleanly.

## 6. SHARED vs VERTICAL-SPECIFIC CODE

```
SHARED (touch once, all bots benefit):
├── lib/bot/telegram.ts          → sendMessage, answerCallbackQuery, download
├── lib/bot/kimi.ts              → Kimi API client (add prompts per vertical)
├── lib/bot/markdown.ts          → escapeMdV1 for Telegram
├── lib/storage.ts               → uploadImage, generateStoragePath
├── lib/image-systems/yamato-*/  → media_queue system
├── app/api/bot/process/route.ts → shared processor (branches by rubroType)
└── lib/supabase/client.ts       → createBotClient

VERTICAL-SPECIFIC (one per bot):
├── app/api/bot/webhook/ropero/     → retail commands, inline menu, photo handling
├── app/api/bot/webhook/inmobiliario/ → real estate commands, search, .txt, inline menu
└── app/api/bot/webhook/lab/          → future: lab-specific commands
```

**Golden rule:** If you're copy-pasting between bots, it should be in shared code instead.

## 8. COST STRUCTURE (Current)

```
Per photo batch (retail):
  Telegram download: free
  Kimi Vision API: ~$0.01-0.03 per batch (depends on photo count)
  Supabase Storage: ~$0.02/GB
  Total: ~$0.05 per batch

Per photo batch (real estate):
  Same as retail + slightly larger Kimi prompt
  Total: ~$0.07 per batch

Monthly estimate (10 tenants, 5 batches/day each):
  1500 batches × $0.06 = ~$90/month in API costs
```

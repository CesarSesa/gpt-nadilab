# Future: pgvector Memory System for Bots
## "The bot that remembers" — conversational memory via semantic search

> Inspired by DeepSeek's explanation of transformer attention mechanics,
> adapted to the scaffold's multi-tenant architecture.
> Priority: Phase 2 (post-Friday, when bot flow is stable)
> Estimated MVP: ~2 hours

---

## THE IDEA IN ONE SENTENCE

Store embeddings of past interactions per user/tenant, retrieve similar memories before each Kimi call, inject as context. The bot "remembers" without actually remembering.

---

## WHY IT MATTERS

```
WITHOUT memory:
  User: [uploads 6 pants]
  Bot: "6 productos detectados"
  User: [next week, uploads 6 more pants]
  Bot: "6 productos detectados"  ← no awareness of history

WITH memory:
  User: [uploads 6 pants]
  Bot: "6 productos detectados"
  User: [next week, uploads 6 more pants]
  Bot: "6 productos detectados — similar al lote anterior de Pantalones Zara.
        ¿Mismo grupo de productos?"  ← context-aware
```

For real estate it's even more powerful:
```
  Agent: [uploads property in Las Condes]
  Bot: "Nota: tu último cliente buscaba departamentos en Las Condes, 3 dormitorios.
        ¿Quieres que le avise?"
```

## STEP 2: Memory Table

```sql
CREATE TABLE conversation_memory (
  id uuid DEFAULT gen_random_uuid() PRIMARY KEY,
  tenant_id uuid NOT NULL REFERENCES tenants(id),
  user_id text NOT NULL,              -- telegram_user_id as string
  memory_type text NOT NULL,          -- 'batch_result', 'preference', 'client_interest', 'correction'
  content text NOT NULL,              -- human-readable summary
  embedding vector(1536),             -- OpenAI text-embedding-3-small dimension
  importance float DEFAULT 1.0,       -- decays over time
  recalled_count int DEFAULT 0,       -- how many times this memory was retrieved
  last_recalled_at timestamptz,
  created_at timestamptz DEFAULT now()
);

-- Semantic search index
CREATE INDEX conversation_memory_embedding_idx
  ON conversation_memory
  USING ivfflat (embedding vector_cosine_ops)
  WITH (lists = 100);

-- Fast lookup by user
CREATE INDEX conversation_memory_user_idx
  ON conversation_memory (tenant_id, user_id);

-- RLS: service_role only (bot writes, not client)
ALTER TABLE conversation_memory ENABLE ROW LEVEL SECURITY;
```

## STEP 3: Match Function

```sql
CREATE OR REPLACE FUNCTION match_memories(
  query_embedding vector(1536),
  match_threshold float DEFAULT 0.7,
  match_count int DEFAULT 5,
  p_tenant_id uuid DEFAULT NULL,
  p_user_id text DEFAULT NULL
)
RETURNS TABLE(
  id uuid,
  content text,
  memory_type text,
  similarity float,
  created_at timestamptz
)
LANGUAGE plpgsql
AS $$
BEGIN
  RETURN QUERY
  SELECT
    cm.id,
    cm.content,
    cm.memory_type,
    (1 - (cm.embedding <=> query_embedding))::float as similarity,
    cm.created_at
  FROM conversation_memory cm
  WHERE (p_tenant_id IS NULL OR cm.tenant_id = p_tenant_id)
    AND (p_user_id IS NULL OR cm.user_id = p_user_id)
    AND (1 - (cm.embedding <=> query_embedding)) > match_threshold
  ORDER BY cm.importance * (1 - (cm.embedding <=> query_embedding)) DESC
  LIMIT match_count;
END;
$$;
```

## STEP 4: Embedding Helper

```typescript
// lib/bot/memory.ts

const OPENAI_EMBEDDING_MODEL = 'text-embedding-3-small';
// Cost: $0.02 per 1M tokens ≈ free

export async function generateEmbedding(text: string): Promise<number[]> {
  const response = await fetch('https://api.openai.com/v1/embeddings', {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${process.env.OPENAI_API_KEY}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      model: OPENAI_EMBEDDING_MODEL,
      input: text,
    }),
  });

  const data = await response.json();
  return data.data[0].embedding;
}

export async function saveMemory(
  tenantId: string,
  userId: string,
  memoryType: string,
  content: string,
): Promise<void> {
  const supabase = createBotClient();
  const embedding = await generateEmbedding(content);

  await supabase.from('conversation_memory').insert({
    tenant_id: tenantId,
    user_id: userId,
    memory_type: memoryType,
    content,
    embedding,
  });
}

export async function recallMemories(
  tenantId: string,
  userId: string,
  currentMessage: string,
  count: number = 3,
): Promise<string[]> {
  const supabase = createBotClient();
  const embedding = await generateEmbedding(currentMessage);

  const { data } = await supabase.rpc('match_memories', {
    query_embedding: embedding,
    match_threshold: 0.65,
    match_count: count,
    p_tenant_id: tenantId,
    p_user_id: userId,
  });

  if (!data || data.length === 0) return [];

  // Update recalled_count for retrieved memories
  const ids = data.map((m: any) => m.id);
  await supabase
    .from('conversation_memory')
    .update({
      last_recalled_at: new Date().toISOString(),
      recalled_count: supabase.raw('recalled_count + 1'),
    })
    .in('id', ids);

  return data.map((m: any) => m.content);
}
```

## STEP 5: Integration Points

### After Kimi analysis (save memory)
```typescript
// In app/api/bot/process/route.ts, after drafts are created:

// Save batch result as memory
const memorySummary = productAnalysis
  ? `Lote de ${productAnalysis.items.length} productos: ${productAnalysis.items.map(i =>
      `${i.suggested_quantity}x ${i.suggested_base_name} (${i.suggested_color || 'sin color'})`
    ).join(', ')}`
  : `Propiedad: ${propertyAnalysis.suggested_title} en ${propertyAnalysis.detected_commune}`;

await saveMemory(tenantId, String(userId), 'batch_result', memorySummary);
```

### Before Kimi analysis (recall context)
```typescript
// In app/api/bot/process/route.ts, before Kimi call:

const memories = await recallMemories(tenantId, String(userId), caption || 'fotos de productos');
const memoryContext = memories.length > 0
  ? `\n\nContexto de lotes anteriores del usuario:\n${memories.join('\n')}\nUsa este contexto si es relevante.`
  : '';

// Inject into Kimi prompt
productAnalysis = await analyzeProductImages(imageBuffers, (caption || '') + memoryContext);
```

## STEP 6: Importance Decay (Optional Cron)

```sql
-- Run weekly: reduce importance of old, unrecalled memories
UPDATE conversation_memory
SET importance = importance * 0.9
WHERE last_recalled_at IS NULL
  AND created_at < now() - interval '7 days';

-- Clean up very old, low-importance memories
DELETE FROM conversation_memory
WHERE importance < 0.1
  AND created_at < now() - interval '30 days';
```

Can be a Supabase scheduled function (pg_cron) or a simple API endpoint called by Vercel cron.

## COST ESTIMATE

```
OpenAI text-embedding-3-small:
  $0.02 per 1,000,000 tokens
  Average message: ~50 tokens
  Per embedding call: $0.000001 (basically free)

Per batch processed:
  1 embedding to save memory:   $0.000001
  1 embedding to recall:        $0.000001
  Total added cost per batch:   $0.000002

Monthly (10 tenants, 5 batches/day):
  1500 batches × $0.000002 = $0.003/month

Storage: pgvector rows are ~6KB each
  1500 memories/month = ~9MB/month (negligible)
```

**This is essentially free.**

## THE VERTICAL ANGLE

Each rubro generates different memory types:

| Rubro | Memory Types | Example |
|-------|-------------|---------|
| Retail | batch_result, correction, pricing_pattern | "User always marks Zara items at 15,000 CLP" |
| Real Estate | batch_result, client_interest, area_preference | "Last 3 properties were in Las Condes, 2-3 dorms" |
| Lab (future) | batch_result, regulatory_note, supplier_pattern | "Supplier X always ships paracetamol in 5000-unit lots" |

The table is the same. The `memory_type` field + the content is what changes. Kimi interprets relevance based on the rubro context already in its prompt.
